# Session, persistence, storage

## One-line purpose

The durable session data plane: an append-only typed event log (`@deepseek-ai/dsh-session`) that is the single source of truth for an agent interaction, a backend-neutral persistence seam that makes that log crash-safe, a build-static format-migration chain that reads released logs, and the projection / query / storage / attachment / spill / compaction seams built on top of it.

## Session event/log model & projections

The log is the only source of truth; message history is derived, never stored. `SessionEventMap` in `packages/core/session/src/types.ts` is a merge-extensible interface: plugins add event types by `declare module '@deepseek-ai/dsh-session/types' { interface SessionEventMap { ... } }`. `SessionEvent<T>` is a proper discriminated union over `type` carrying `{ type, seq, time, data, ignorable? }` plus conditional `surfaceOp` / `sourceEventSeqs`. `seq` is contiguous from 0 and never rewritten.

`SurfaceEventType` is the message-producing subset — `system/message`, `developer/message`, `user/message`, `assistant/message`, `tool/result`. Those events must supply a `SurfaceIntent` (`surfaceOp: 'append' | { op: 'replace', startSeq, endSeq }`, plus `sourceEventSeqs` except on `assistant/message`, whose embedded `stream` owns provider evidence). Non-surface events forbid surface metadata at compile time, so `compaction/*`, `hook/*`, `request/*`, `session/end-seed` and friends are log-only.

`Session` (`packages/core/session/src/index.ts`) is a plain class, not a Service: `ctx.sessions.create()` makes live instances, `Session.create()` / `Session.fromRestore()` make detached ones. `append(type, data, ...surfaceIntent)` snapshots and deep-freezes JSON (`snapshotJsonValue` rejects non-serializable payloads at the call site), validates event data, then commits. `surface` exposes `nodes`, `replaceGeneration`, `contentGeneration`; `deriveMessages()` folds the surface into LLM history. `header` (format version, id, cwd, `isSeeded`, lineage) is storage metadata kept outside the log. `inheritedEventCount` is the exact fork cut; `firstLiveSeq` / `firstLifecycleSeq` are in-process only and not persisted. `eventAt` / `snapshotEvents` are deprecated in favor of async reads.

Vocabulary enforcement is generated: `packages/core/session/src/known-event-types.ts` exports `KNOWN_SESSION_EVENT_TYPES` (every repository-declared type, generated by `scripts/gen-persistence-catalog.ts`). A reader meeting an unknown type refuses unless the envelope carries `ignorable: true`; absence means required-on-read.

Projections (`packages/session/session-projection/src/index.ts`) fold committed events into whole current values. `ProjectionDefinition` = `{ key, stateSchema, init(header, inheritedEventCount), apply(state, event), wire?: { viewSchema, view, summary? }, stateVersion }`. Functions must be synchronous; state must be plain JSON; an uninterested event must return the same state reference (`Object.is` gates downstream work). `register()` is effect-owned and returns `ProjectionHandle` (`stateOf`, `readerFor`, `dispose`). The registry drives every unit, keeps a per-session watermark, and serves `snapshot()` (one consistent `asOfSeq` cut over all client-visible keys), `summaryKeys()`, `checkpoint()` / `restore()`. Load-bearing rule: a state-carrying log event carries the complete post-change value, never a bare delta. `session-projection-cache` persists `(sessionId, key, ver, seq, val)` rows through a `storage-domain` spec; a row is a fold shortcut, never authoritative — `ver` mismatch or a watermark past the log end discards it.

Titles, stats, turn outline, and the subagent catalog are projection/service consumers, not separate logs: titles persist as log-only `session/title` events and never enter model input.

## Persistence backends, format versions, migration rules

`SESSION_FORMAT_VERSION = 4` in `packages/core/session/src/types.ts:90` is the only hand-maintained writer number in code. `docs/session-format-status.md` records the finalization (`latestFinalizedVersion: 4`, checkpoint `docs/persistence-changes/finalized/v4.json`) and the release (`latestReleasedVersion: 4`, `evidenceTag: dsh-v0.2.0-rc.2`). Writer == released here, so V4 has shipped.

`SessionPersistence` (`packages/session/session-persistence/src/index.ts`) is an abstract `Service` on `ctx.sessionPersistence` with `create(header, options)`, `open(id, 'read'|'write', options)`, `stat(id)`, `list()`, `flush()`. Everything else flows through the returned `SessionHandle` (`src/handle.ts`): `read(offset?, length?)` → `{ eventState, events }` where `eventState` is `detached` or `shared-frozen`, `append(events)` requiring the first `seq` to equal stored next-seq, `flush()` (the durability barrier; also materializes an empty created session), idempotent uncancellable `close()`. Ownership failures are stable classes: `SessionAlreadyExistsError`, `SessionAlreadyOwnedError`, `SessionReadOnlyError`, `SessionHandleClosedError`, `SessionOwnershipLostError`, `SessionPersistenceNotFoundError`, `SessionFormatUnsupportedError`, `SessionPersistenceCorruptionError`. `storage-contract.ts` holds the shared validators every backend runs: `assertVersion`, `assertStoredId`, `assertContiguous`, `validateStoredEvents`, `materializeAppendBatch`, `materializeCreateHeader`.

The shipped JSONL backend (`packages/session/session-persistence-jsonl`) is the sole first-party provider. Config: required `root` (no default), `compression: 'zstd' | 'none'` (default zstd), `listConcurrency` (3). Layout: `<root>/--<normalized-cwd>--/<encoded-id>/session[.vN].jsonl[.zstd]`, one session-owned directory per id, generation selection = numerically highest canonical filename. Each generation starts with a physical header line whose version equals its filename; the current format writes one physical row per durable event, and each append is one checksummed Zstandard frame `fsync`ed before resolution. `create` writes nothing (lazy materialization); the first `append` publishes the header + batch with a no-overwrite publish (POSIX `link()`, Windows write-through rename). Historical input is decoded and migrated once on read open; a write open additionally re-encodes, verifies in a Worker Thread, rechecks the source revision, and publishes the successor without overwriting — the source stays byte-identical. Crash recovery returns the physically valid contiguous log; a torn tail's complete records are durably rewritten before the first new append, and semantic repair (synthetic `interruptedTurnClosers`: missing tool results, open `step/end`, `turn/end { interrupted }`) belongs to the reader (agent-loop resume) or to session-query in memory only.

Format migration is build-static, never composition-dependent. `packages/session/session-format/src/chain.ts` compiles a complete, unique adjacent chain: `defineSessionFormatMigration` requires `toVersion === fromVersion + 1`; `createSessionFormatChain` rejects gaps, duplicates, and edges that do not reach `currentVersion`. Each `SessionFormatMigration` is `{ name, fromVersion, toVersion, migrateHeader, createStage, validateTargetHeader }`; `SessionFormatCatalog` adds per-version `SessionFormatCodec`s and the current encoder. `session-format-catalog/src/generated.ts` wires codecs v0–v4 and migrations v0→v1→v2→v3→v4 (generated by `scripts/gen-session-format-catalog.ts`, which also checks the catalog reaches `SESSION_FORMAT_VERSION`). Current input bypasses the chain entirely; same-version readers must retain earlier representations.

Version rules (from `packages/core/session/src/types.ts`, `docs/session-format-status.md`, `docs/persistence-changes/README.md`): bump only when an existing discriminator cannot prevent unsafe interpretation — a structural difference alone is insufficient. Same-version evolution is allowed and is acknowledged with a dated record under `docs/persistence-changes/`; optional event-body additions, required→optional, ordinary new event types, and a new qualified `data.version` alternative are `same-version`; required additions/removals/type changes need compatibility review or `version-bump`. An adjacent migration may add a version-named successor but never move, overwrite, or delete committed generations; predecessors imply neither fallback nor downgrade. SQLite uses a separate monotonic `SCHEMA_VERSION`.

Generated artifacts that must not be hand-edited: `docs/persistence-catalog.md`, `docs/persistence-schema.json`, `packages/core/session/src/known-event-types.ts`, `packages/session/session-format-catalog/src/generated.ts`. Regenerate with `pnpm run gen-persistence-catalog` / `pnpm run gen-session-format-catalog`; `verify-persistence-catalog` and `verify-cordis-catalog` run in `doc-sync`.

Durability scheduling is separate from storage: `session-checkpoint-policy` flushes before a model request, before a top-level tool can cause external effects, and before the next step begins, and fails closed so the adapter or tool body does not run until the durable write succeeds. `session/event` is a synchronous notification the backend routes into a bounded write-behind window; `session/flush` drains through quiescence and is the loop's ordering/error-observation checkpoint; `session/disposed` does the final drain and close.

Only handle-acquired sessions persist: `agent-loop` calls `persistence.create(session.header, ...)` before publication and appends the unpublished suffix; `ctx.sessions.create` + `session/flush` alone stores nothing.

## Storage/attachment/spill seams

`ctx.storage` (`packages/storage/storage`) is a hub, not IO: `BackendRegistry` holds named backends and `mount(form, facility)` exposes data forms (`ctx.storage.domain`). `StorageBackend` owns one medium and exposes optional facets — currently `kv` — plus idempotent `close()`. `KvUnitDescriptor` = `{ name, version, tables, hasGlobal, layout?: 'single'|'per-record', compatibleVersions? }`; names must match `UNIT_NAME_RE = /^[a-z][a-z0-9_]*$/`. A unit does not serialize concurrent writes — ordering is the caller's job, and `storage-domain` runs one write chain per unit. `storage-domain` adds zod-declared domains (`defineDomain`, `domainTable`), schema validation, and change events; the shipped composition routes projection checkpoints `per-record` under `<root>/session_projcache/sessions/`. `storage-json` publishes each changed file atomically; `storage-sqlite` keeps units as JSON documents with row-level versioning.

`ctx.attachments` (`packages/attachment/attachment`) is `AttachmentStore` with `imageLimits`, `validateImage`, `saveImage`, `readImage`; refs are content-addressed and messages keep references, not bytes. `attachment-local` stores below `DSH_HOME` (default `$DSH_HOME` → `~/.dsh`), dedupes identical bytes, normalizes images per request route, preserves generic files byte-for-byte, and never deletes automatically.

`ctx.spillStore` (`packages/spill/spill`) is `saveText(input) → SpillRef` (owner + locator + retrieval guidance). `spill-local` writes private session-scoped files under a temp root prefixed `dsh-spill-` with traversal-safe names and owner-only exclusive writes; `spill-policy` listens on `ctx.tools`, replaces oversized plain-text tool results with a preview + locator when `maxInlineTokens` is configured, and keeps the original result on storage failure. `session-reference` consumes spill storage directly for truncated captured transcripts.

`ctx.workspaceRegistry` (`packages/workspace/workspace`) keeps named, ordered projects and groups sessions by header cwd; archive/pin are membership operations that never delete folders or session history, and it requires session storage plus a persistence backend.

Compaction (`packages/compaction/compaction`) is `ctx.compaction`: a backend decides when to compact and replaces a surface span with one summary node. The transaction is logged as log-only `compaction/start` → `compaction/summary` (inputs, shadowed range/seqs/token count, provider/model/usage) → `compaction/end`, with the actual surface replacement carried by the immediately following `user/message` whose `source.kind === 'compact-checkpoint'` (`compactCheckpointSource(compactionId, sourceCommandId)`, recognized by `isCompactCheckpointSource`). `compaction/prune` carries the shadow price for model-free prune replacements. That adjacency is contractual. `compaction-basic` owns trigger policy, retention, region selection (`region.ts`) and summarization; `compaction-image-offload` appends `image/offload` and projects placeholder messages; `command-compact` runs `/compact` through `runMaintenance` so it serializes against driver turns.

Deliverables are log-only Session events consumed by clients: `deliverables/presented` (from `present`) and `workspace/changes` (per-turn changed files). Context plugins (`packages/context/*`) inject durable model-visible context as ordinary user-role messages, so it persists, replays, and compacts like conversation content. `settings` edits live plugin config through schema-derived forms; `credentials` keeps secrets behind `CredentialRef` names with `credentials-local` as the default private store.

## How to extend

1. **Add a session event type.** Declare-merge `SessionEventMap` in the owning package's `src/types.ts` with JSDoc; if it produces model history it must join `SurfaceEventType` and callers must pass `surfaceOp`. Then run `pnpm run gen-persistence-catalog` (refreshes `known-event-types.ts`, `docs/persistence-catalog.md`, `docs/persistence-schema.json`). An ordinary new event type is a `same-version` change and needs a dated record only when the declared type structure changed. Update both SDK expected outputs — `pnpm run test` covers neither.
2. **Add a projection unit.** Implement a `ProjectionDefinition` with pure synchronous `init`/`apply` (same reference for unrelated events), a zod `stateSchema`, plain-JSON state, a bumped `stateVersion` when fields or fold semantics change, and `wire` + `viewSchema` only if clients read it. Register with `await ctx.sessionProjections.register(def)` on a plugin fiber that `inject = ['sessionProjections']`, keep the handle private, and read through `readerFor(session)` / `stateOf(session)`. Follow `.agents/skills/dsh-session-projection/SKILL.md` and verify recovery: restore a checkpoint, replay its suffix, compare with full replay.

## Constraints & gotchas

- **Model-visible ⟺ logged.** Anything reaching a model request must be reconstructable from the session log; a new model-visible input requires a session event.
- **Append-only, contiguous `seq`.** Committed events are never rewritten; a gap rejects. `flush` is the only durability barrier; `append` is best-effort on resolution (JSONL happens to persist each batch immediately).
- **Only handle-acquired sessions persist.** `ctx.sessions.create` + `session/flush` alone stores nothing; `agent-loop` is the production acquisition point.
- **Unknown vocabulary fails closed.** An unrecognized event type refuses the read unless the envelope carries `ignorable: true`; `SessionEventMap` members are required-on-read.
- **Bump `SESSION_FORMAT_VERSION` only when a discriminator cannot prevent unsafe interpretation.** Same-version changes need safe old/new reader behavior and a recorded review; finalized records and accepted after-schemas are immutable.
- **Generations are immutable.** Migrations add version-named successors; they never move, overwrite, or delete committed generations, and predecessors provide no fallback or downgrade.
- **Projections are synchronous and non-authoritative.** No I/O or hooks in `init`/`apply`, plain-JSON state, same-reference returns for unrelated events, `stateVersion` bump on semantic change; a persisted checkpoint is only a fold shortcut.
- **JSONL operational constraints.** `root` is required with no default; one encoding per root (compression conversion unsupported); POSIX materialization needs hard-link support and the prebuilt `node-addon-system` addon for async `flock`; Windows uses a per-login-session named semaphore; advisory `flock` is unreliable on NFSv3.
- **No deletion or retention API** on the persistence seam or JSONL backend; logs accumulate until removed out of band. `list()` is unpaginated and unfiltered.
- **session-query exact reads replay whole logs.** `readSession`, `readSurface`, `filterEvents`, and event traces load and validate the complete log; the `text` filter is a literal regex scan, not ranked search.
- **SQLite search is a separate derived index.** `openAt: never` in the shipped base (`packages/bundle/base/cordis.patch.yml:161`, `path: ':memory:'`) keeps exact reads but disables search; the `unicode61` tokenizer matches tokens, so `AI` does not match `BRAID`; each index path has one process owner.
- **Generated files are off-limits to hand edits**: `docs/persistence-catalog.md`, `docs/persistence-schema.json`, `known-event-types.ts`, `session-format-catalog/src/generated.ts`. Regenerate instead.
- **Attachments and spill are never auto-deleted**, and spill files are private session-scoped paths, not session content.
- **Storage units do not serialize concurrent writes**; the domain layer must order them. `UNIT_NAME_RE` constrains unit/table names because they become file names and SQL identifiers.

## Open questions

1. Is a V5 format planned? The checkout shows writer, finalized, and released all at 4; no successor edge exists. Unverified beyond the checkout.
2. Should the shipped base enable full-text search? It currently mounts `session-query-sqlite` with `path: ':memory:'` and `openAt: never`, so ranked search is opt-in per deployment — the product decision is not recorded here.
3. Historical migration cost scales with the root's Session count (fresh preparation scans all selected headers and decodes direct-child bodies); no measured bound for large roots was verified.
4. Who prunes session logs? The seam has no deletion/retention API and the README calls pruning out-of-band backend maintenance; no owning package was found.
5. The `storage-domain` design Agent Note is still marked proposed, with the session-backend migration and a `log` facet listed as deferred — current status unverified.
