Confirmed on `master` @ `8bd073392e` (root `0.2.2-alpha.3`, Linux, Node 24.22.2, pnpm 11.28.5).

Root cause matches PerryLink's analysis. Reproduced deterministically without the desktop shell:

```ts
import { volatileForm } from 'packages/settings/settings/src/schema.ts'
const config = {
  '~standard': { version: 1, vendor: 'example', validate: (v: unknown) => ({ value: v }) },
  toJSON() { return { type: 'object', properties: {} } },
}
volatileForm(config as never) // TypeError: Cannot read properties of undefined (reading 'volatile')
```

`SettingsForms.schema()` accepts any `Config` with `toJSON()` and casts it to Schemastery; `describe()` then calls
`volatileForm()`, whose first line reads `schema.meta.volatile` — the Standard Schema object has no `meta` graph, so
enumeration throws and the RPC returns `gateway/internal` before the welcome window is served.

One correction for anyone fixing this: `~standard` cannot be used to tell the two apart, because vendored Schemastery
implements Standard Schema itself (`vendor/schemastery/lib/index.mjs:52`, consumed by `vendor/cordis/src/fiber.ts:53`).
The safe structural discriminator is Schemastery's global symbol marker
(`Symbol.for('schemastery')` set on `Schema.prototype`, `vendor/schemastery/lib/index.mjs:3,50`) plus its injected
`meta` (`:48`); that also works across package copies.

Proposed minimal fix (tested locally on a branch):

- add `isSchemasterySchema(value)` in `packages/settings/settings/src/schema.ts` using that marker + `meta`;
- make `SettingsForms.schema()` return `undefined` for unsupported Configs, so `describe()` skips them instead of
  crashing (they had no renderable form before either — describe always threw);
- leave `volatileForm`/`isVolatilePath` untouched;
- regression tests: guard-level in `schema.spec.ts` and a real-composition `describe()` test with a Standard-Schema
  Config that asserts other entries still render and `update()` rejects with a clear error.

Verification: settings package tests 48/48, affected suites 855/855, `pnpm run typecheck` 5/5 gates, `pnpm run
test:docs` 21/21 gates, oxlint clean. Both new tests fail on unfixed code with the exact TypeError above.
